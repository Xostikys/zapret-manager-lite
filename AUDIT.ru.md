# Проверка Zapret Manager Lite, редакция 3

Дата: 16 ноября 2026. Проверены локальные исходники дополнения и пакет публикации.
Роутер не изменялся, GitHub автоматически не обновлялся. Проверка всех возможных
ошибок и уязвимостей не доказуема; этот документ фиксирует найденное и границы работы.

## Найдено и исправлено

| Проблема редакции 2 | Значимость | Исправление |
|---|---|---|
| UCI -c менял конфигурационный каталог, но сохранял изменения в общем delta-хранилище | Высокая: возможен конфликт чужих настроек | Отдельные -c и -t, отказ при pending changes, сравнение остальных секций |
| Три этапа применялись независимо | Высокая: частично изменённая панель | Общая подготовка, одна копия и операция с проверкой состояния |
| Откат начинал менять компоненты до проверки остальных; слушатель не восстанавливался | Высокая: смешение версий, неполный откат | Общая проверка до записи, копирование listener/удалённых файлов |
| Временные маркеры в общедоступном /tmp и неполные проверки ссылок | Средняя: защита от локальной подмены была недостаточной | Root-only каталог, проверка владельца/режима и каждого предка пути, mktemp |
| lock мог оставаться после аварийного завершения | Средняя: остановка автоматической очистки | Проверка PID, уборка собственного осиротевшего staging, recovery-журнал |
| Изменённую upstream-функцию можно было вырезать по грубому шаблону | Высокая: ошибочное изменение backend | Точное сравнение удаляемых функций с известным исходником, отказ на неизвестном |
| Файлы копировались перед выяснением, нужны ли изменения | Низкая: лишние CPU/RAM/I/O | Быстрая сверка до копирования, одно задание cron, кэш наблюдений в RAM |
| Сообщения/README описывали старое поведение | Средняя: неверные ожидания | Переписаны инструкции, оговорены reload, длительность и ограничения |

Поведение -c/-t сверено с [официальным исходником UCI](https://github.com/openwrt/uci/blob/master/cli.c).
Подготовка через -t не записывает собственные delta в общий каталог. Конкурирующий
внешний процесс всё ещё может изменить настройки; поэтому дополнительно проверяются
pending changes и контрольные суммы до применения. Общей блокировки с исходным
установщиком нет; полностью исключить гонку внешнего root-процесса нельзя.

## Проверки

- Синтаксис shell, JSON и генерируемых JavaScript-модулей.
- Целостность self-extracting архива, совпадение с опубликованными исходниками,
  контрольные суммы, LF, допустимые имена и обычные типы файлов.
- Установка в модель файловой системы; повторное применение без перезаписи.
- Сохранение пунктов Forkozz и чужого cron; удаление только собственного cron.
- Возврат listener, компонентов и удалённых страниц при откате.
- Режим check без записи файлов Manager; два стабильных наблюдения перед auto.
- Отказ при новом шаблоне, изменённой удаляемой функции и pending UCI settings.
- Отказ откатывать новую версию поверх старой; отказ до частичных записей.
- Искусственная ошибка записи и reload, восстановление прежних данных.
- Сравнение неизменности тестовых игровых и firewall-конфигов.

Точный результат последнего прогона находится в TEST-RESULTS.json. Тесты выполнялись
в Windows с настоящими sh и tar. UCI и ucode использовали модель; uid/режимы Unix
и процессы OpenWrt не воспроизводились полностью. Статические проверки и браузер
не заменяют тест реального BusyBox/ucode/uhttpd/rpcd и вход в ARC Raiders.

## Что осталось

1. Оригинальный Manager содержит обширные функции root-администрирования,
   загрузку и запуск удалённых скриптов. В сохранённом коде есть зеркала
   gh-proxy.org, ghfast.top, gh.llkk.cc, ghproxy.net и запуск обновления через sh.
   Это значимая зависимость от доверия к поставщикам, а не доказанный удалённый
   эксплойт. Независимая подпись каждого стороннего компонента этим патчем не добавлена.
2. Полный аудит примерно 70 тысяч строк upstream, всех RPC-методов и движков,
   проверка доступности портов с WAN, ACL на устройстве и CVE установленных
   пакетов не выполнены. Нет оснований объявлять их безопасными или уязвимыми
   только по найденным eval/curl: нужен анализ конкретных входов и версий.
3. Удаление слушателя распознаёт только известную секцию uhttpd.zmweb.
   Нестандартные серверы/порты не отключаются вслепую.
4. После upstream-обновления есть окно до очередной очистки. Неизвестная версия
   может потребовать адаптации; автоматическое удаление не гарантировано навсегда.
5. Файлы меняются атомарным переименованием по одному, а не одной атомарной
   операцией для всей ФС. Отключение питания/flash-ошибка требуют проверки и recovery;
   нет гарантии сохранности при физическом отказе накопителя.
6. Откат восстанавливает последний снимок; ранее применённая очистка может
   уже входить в этот снимок. Архивы версий 1/2 не смешиваются с новой копией.
7. Редакция 3 не проверена на физическом роутере; массовую публикацию как
   стабильного выпуска следует делать после такой проверки.

## Оптимизация

Уже сделано: один короткий cron вместо цепочки из трёх скриптов, ранний пропуск
неизменных файлов, отсутствие постоянного наблюдателя, отсутствие повторной записи
неизменного UI, ограничение временного снимка и контроль свободного места.

На предоставленном замере MemAvailable=86676 KiB (~84.6 MiB), RSS sing-box=65124 KiB
(~63.6 MiB). Оснований принудительно урезать память sing-box нет. CSS-анимации
нагружают браузер, а не являются основной статьёй RAM роутера. Изменения сетевых
буферов, flow offloading, conntrack, fake-файлов и стратегии могут сломать игры;
их в эту оптимизацию не включали. Снижение частоты фоновых проверок исходного
Manager можно отдельно оценить, но без измерения нельзя обещать экономию RAM.

Исправление совместимости: обязательная команда stat удалена. Владелец и права
каталогов проверяются через числовой вывод ls -nd; защитные проверки сохранены.
Локальная модель проверила допустимые и запрещённые варианты метаданных.

Исправление обновлений: массовая замена видимого текста затрагивала служебный
маркер полноты скачанного установщика. Исходная проверка восстановлена,
исправляются и ранее изменённые компоненты. Настоящий установщик 5.085 проходит
проверку; обрезанная копия отклоняется. Удалённый установщик в тесте не запускался.

Добавлен однократный запуск after-update.sh после успешной установки из LuCI.
Проверены порядок вызовов, аргументы, пропуск при ошибке установки/disabled,
сообщение при ошибке очистки. Нет постоянно работающего процесса.
Проверка преобразований UI и компонентов 5.085 прошла на локальной модели.
