# Zapret Manager Lite

Локальная модификация **Zapret Manager от StressOzz** для OpenWrt/LuCI:
без рекламных ссылок VPN/Telegram и донатных блоков, с прозрачными карточками
и отключёнными CSS-анимациями. Авторство и лицензии сохранены.

## Установка одной строкой

В SSH-консоли OpenWrt под root:

```sh
wget -O /tmp/zm-lite-install.sh https://raw.githubusercontent.com/Xostikys/zapret-manager-lite/main/install.sh && sh /tmp/zm-lite-install.sh
```

Из Windows PowerShell одной строкой:

```powershell
ssh root@192.168.1.1 "wget -O /tmp/zm-lite-install.sh https://raw.githubusercontent.com/Xostikys/zapret-manager-lite/main/install.sh && sh /tmp/zm-lite-install.sh"
```

Команды заработают ПОСЛЕ публикации файлов в публичном репозитории
`Xostikys/zapret-manager-lite`, ветка `main`.

## Что устанавливается

Если Manager уже есть, применяется только модификация его текущего UI.
На вашем рабочем роутере повторная установка исходного Manager не выполняется.
На чистой системе запускается включённый установщик с вырезанным отдельным фронтендом **5.081**, затем
модификация. Чистая установка этого составного пакета на физическом роутере
пока не проверена. Движки Zapret/Forkozz, стратегии и серверы настраиваются
отдельно через исходный Manager — установщик не переносит чужой рабочий конфиг.

Требуются OpenWrt, LuCI, root, HTTPS-загрузка с GitHub и работающий cron.
Исходный установщик ставит свои зависимости. Для существующей панели нужны
ucode с fs, tar, sha256sum, cmp, xargs, crontab. Режим панели в RAM через
символьные ссылки и включённая отдельная Web-служба требуют предварительно
переключить панель в обычное хранение на flash и выключить standalone Web.

## Поведение и обновления

- Текущие пункты меню, включая Forkozz, сохраняются.
- Убираются известные рекламные блоки, вкладка поддержки и standalone Web-активы.
- Авторские сведения остаются в исходниках, NOTICE и странице credits.
- Оформление затрагивает Manager, использует фон/текст темы LuCI.
- Настройки nfqws, DNS, маршрутизация и службы действующей установки нашей
  модификацией не изменяются.
- Проверка через cron раз в 5 минут; после двух одинаковых наблюдений правка
  повторяется, обычно через 5–10 минут после обновления Manager.
- Неизвестная структура UI вызывает отказ до записи файлов; сообщение
  появляется в `logread -e zm-local-ui`. Для таких версий нужен новый патч.
- Обновление самого Manager остаётся от StressOzz; периодическая правка
  поддерживается локальным дополнением. Собственного независимого backend нет.

Повторный запуск команды обновляет локальную модификацию из этого репозитория.
Исходный Manager при этом остаётся текущей версии. Перепрошивка и удаление
пользовательского cron могут потребовать повторной установки дополнения.

## Отключение и откат модификации

```sh
sh /etc/zm-local-ui/restore.sh
```

Удаляется только наше задание cron, затем возвращается UI перед последним
применением, если файлы с тех пор не изменились. Это не удаление движков и
не удаление исходного Manager. Его удаление выполняется штатно через Manager.

## Исходники и сборка

`src/` — локальная очистка, CSS, преобразователь ucode, установка/откат.
`vendor/` — изменённый установщик 5.081 и его лицензия/NOTICE.
`SOURCES.json` — commit и SHA256 сохранённого оригинала.
`bootstrap.sh.in` + `build.py` — сборка автономного `install.sh` без зависимостей
Python на роутере. Python нужен только для пересборки на ПК:

```sh
python build.py
```

После изменения `src/` запустите сборку: она обновит `src/PACKAGE.sha256`
и пересоберёт install.sh. Встроенная SHA256
проверяет целостность встроенного архива, не является независимой подписью.

## Проверено

Пользователь подтвердил применение локального дополнения на Cudy WR3000S v1
ubootmod, OpenWrt 25.12.4 aarch64_cortex-a53, Manager 5.083. Локально проверены
оформление в браузере, сохранение меню Forkozz, повторное применение, отказ
на неизвестном шаблоне и восстановление после ошибки в модели файловой системы.
Это не означает проверки всех устройств и будущих версий Manager.

## Редакция 2 — только LuCI

Из сохранённого установщика удалены генератор отдельного фронтенда, его
настройка слушателя и команды включения. Дополнение удаляет эти команды
также из существующих backend/RPC и убирает оставшиеся тексты со страниц.
Внутренние идентификаторы совместимости и имена удаляемых старых файлов
сохранены в миграции; отдельной страницы и возможности включения нет.
Компоненты до изменения сохраняются в /etc/zm-local-ui/components-before.tar.gz.
Первая миграция перезагружает RPC-процесс, может потребоваться повторный вход
в LuCI. Рабочие конфиги движков не переписываются.
Неизвестные шаблоны требуют адаптации; миграция сначала проверяет shell/JSON.
Изменение backend/RPC выходит за пределы прежней чисто визуальной правки.
На физическом роутере редакция 2 ещё не проверена.
